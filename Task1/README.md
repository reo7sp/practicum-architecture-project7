# Задание 1. Исследование моделей и инфраструктуры

Считаю, что отчёт делается для компании, которая выбирает стек для RAG-бота с учётом цены, качества и конфиденциальности данных.

## 1. Сравнение LLM: локальные Hugging Face vs OpenAI / YandexGPT

| Критерий | Локальные HF | OpenAI / YandexGPT |
|---|---|---|
| Качество ответов | обычно ниже, но для RAG часто достаточно | обычно выше и стабильнее |
| Скорость работы | быстро на GPU, медленно на CPU | быстро, но зависит от сети |
| Стоимость | дороже запуск, дешевле при большой нагрузке | удобно для пилота, но дорого при росте |
| Развёртывание | сложнее | проще |

**Вывод:** для быстрого старта удобнее облачные модели, для закрытого контура — локальные.

## 2. Сравнение эмбеддингов: Sentence-Transformers vs OpenAI Embeddings

| Критерий | Sentence-Transformers | OpenAI Embeddings |
|---|---|---|
| Скорость создания индекса | быстро локально, особенно на GPU | зависит от API и сети |
| Качество поиска | хорошее | обычно выше |
| Стоимость | инфраструктура, без оплаты за токены | оплата за использование |

**Вывод:** локальные эмбеддинги выгоднее при регулярной индексации и если данные нельзя уносить в облако.

## 3. Сравнение ChromaDB и FAISS

| Критерий | ChromaDB | FAISS |
|---|---|---|
| Скорость поиска и индексации | хорошая | выше |
| Внедрение и поддержка | проще | сложнее |
| Удобство в работе | есть метаданные и фильтры | нужен свой обвес |
| Стоимость владения | чуть выше по инфраструктуре | ниже как библиотека, но больше разработки |

**Вывод:** для RAG-бота удобнее ChromaDB, потому что она проще в использовании и сразу подходит для работы с документами и метаданными.

## 4. Рекомендуемая конфигурация сервера и итоговые рекомендации

### Вариант 1 — полностью облачный
- LLM: OpenAI / YandexGPT
- Embeddings: OpenAI
- БД: ChromaDB
- Сервер: 8 vCPU, 32 GB RAM, без GPU

**Плюсы:** быстро запустить
**Минусы:** данные уходят в облако

### Вариант 2 — гибридный
- LLM: OpenAI / YandexGPT
- Embeddings: Sentence-Transformers
- БД: ChromaDB
- Сервер: 16 vCPU, 64 GB RAM, 1 GPU 24 GB

**Плюсы:** баланс качества, стоимости и приватности
**Минусы:** LLM всё ещё облачная

### Вариант 3 — полностью локальный
- LLM: Hugging Face
- Embeddings: Sentence-Transformers
- БД: ChromaDB
- Сервер: 32 vCPU, 128 GB RAM, 1 GPU 48 GB

**Плюсы:** данные остаются внутри контура
**Минусы:** сложнее и дороже поддержка

### Вариант 4 — локальный с FAISS
- LLM: локальная или облачная
- Embeddings: локальные
- БД: FAISS
- Сервер: 32 vCPU, 128 GB RAM, 1 GPU 48 GB

**Плюсы:** высокая скорость
**Минусы:** сложнее внедрение

**Итоговая рекомендация:**
Для этой задачи я бы выбрал ChromaDB как векторную БД, потому что она проще для RAG-бота и удобнее в работе с метаданными.
Лучший вариант архитектуры — гибридный: облачная LLM, локальные эмбеддинги, ChromaDB.
Он даёт хорошее качество ответов, не слишком дорогой и лучше подходит для конфиденциальных данных, чем полностью облачный вариант.
